TXZK Standard Project

A KiCad project template with standard TXZK drawing sheets for schematics and PCB documentation. Both drawing sheets include a title block in the bottom-right corner and a revision history table in the top-right corner. The field mappings below apply to both the A3 and A4 drawing sheets.

Default Page Setup

Document Paper Size Drawing Sheet
Schematic A3, landscape TXZK-STD-A3-Sheet.kicad_wks
PCB A4, landscape TXZK-STD-A4-Sheet.kicad_wks

Set KICAD_DYW_DIR to the root of your KicadLib folder in Preferences > Configure Paths. The drawing sheets are loaded from ${KICAD_DYW_DIR}/template/.

Title Block — Bottom Right

Open Page Settings in the Schematic Editor or PCB Editor to enter the title, company, revision, issue date, and comments. Set these values for the schematic and PCB separately.

Field Variable Content
Project (shown as "Projet") ${PROJECTNAME} The KiCad project name, without the file extension.
Title ${TITLE} The drawing title entered in Page Settings.
Company ${COMPANY} The company or organization name, displayed in the large lower-left cell.
Doc No. ${COMMENT1} The document or drawing number. Enter it in Comment 1.
VCS ID ${VCSSHORTHASH} The short Git commit hash for the project, when available.
Rev. ${REVISION} The current document revision, entered in Revision.
Sheet ${#}/${##} The current sheet number and total sheet count.
PCB layer (in the Sheet cell) ${LAYER} The layer name on PCB plots; blank in the schematic and editor views.

Designed by identifies the designer; Checked by identifies the reviewer; Process Eng. identifies the process or manufacturing engineer; and Approved by identifies the release approver. These are blank sign-off spaces with no variable assignments in this template. They are separate from the Revised and Approved fields in the revision history table.

Revision History — Top Right

The table has two entry rows. The first shows the current revision record; the second shows the immediately preceding revision record. Comments 7, 8, and 9 hold that previous record's revision, date, and change description, respectively. Each row also records the revision author and approver.

Column First Row: Current Revision Second Row: Previous Record
Rev. ${REVISION} — Revision ${COMMENT7} — Comment 7: previous revision number
Date ${ISSUE_DATE} — Issue Date ${COMMENT8} — Comment 8: previous issue date
Description ${COMMENT2} — Comment 2: current change summary ${COMMENT9} — Comment 9: previous change summary
Revised ${COMMENT3} — Comment 3: current revision author ${COMMENT5} — Comment 5: previous revision author
Approved ${COMMENT4} — Comment 4: current revision approver ${COMMENT6} — Comment 6: previous revision approver

Before entering a new revision, manually carry forward the current record:

  • Revision → Comment 7: previous revision number.
  • Issue Date → Comment 8: previous issue date.
  • Comment 2 → Comment 9: previous change summary.
  • Comment 3 → Comment 5: previous revision author.
  • Comment 4 → Comment 6: previous revision approver.

Then enter the new record in Revision, Issue Date, and Comments 2, 3, and 4. Updating Revision does not move the old entry automatically. Comment 1 remains the document number in the title block. Leave Comments 5 through 9 empty when no previous revision needs to be shown.

Variable reference: KiCad text variables.
